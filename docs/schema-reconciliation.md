# Schema reconciliation — 11 October 2026

## Problem

The `dev` branch merged the fork (`e6d50af`) whose frontend was written against a
database schema that matched **neither** the maintained ("old") schema nor the
fork's own hooks. The fork also changed field types in place
(`users.role` select→text, `case_experts.role` select→text, `cases.*` date/select→text,
`program_id` relation→text). PocketBase drops the column on a type change, so
values such as every user's `role` were wiped — which is why the admin sidebar
disappeared and RBAC appeared broken. The hand-written `pb_migrations/*` only
added the new collections and were explicitly untested against production
("Production schemas must be reconciled … before migration").

Because there was no production data to preserve, the database was rebuilt from
a single canonical snapshot instead of patching the old one.

## Method

The frontend code (TypeScript types, `lib/pb-collections.ts`, the hooks) is the
source of truth. The canonical schema is the union of both schemas with type
conflicts resolved toward what the code reads/writes. It was generated by
driving PocketBase v0.31.0's collections API, exported, and verified to
round-trip through `PUT /api/collections/import` on a fresh instance.

Deliverables:

- `backend/pb/pb_schema.json` — 28 app collections (source of truth).
- `backend/pb/seed.mjs` — idempotent defaults + first admin.
- `backend/pb/import-schema.mjs` — applies the snapshot.
- `backend/pb/pb_hooks/` — hooks, updated for `case_experts.role_id`.
- `backend/pb/pb_migrations_legacy/` — the superseded partial migrations.

Collections: `users, lookups, blog_categories, tool_types, roles_management,
cases, case_experts, case_tools, case_feedback, expert_profiles,
expert_bank_details, expert_display_settings, experts_public (view),
event_certificates, event_registrations, home_pages, info_pages, blog_pages,
individual_profiles, organization_profiles, parent_profiles, internal_messages,
portals, programs, public_lectures, public_lectures_public (view), settings,
tools`.

Dropped: `case_log` (unused) and `blog_pages.author_id` (unused; `author_name`
kept).

## Notable resolutions

| Collection / field | Old | Fork | Canonical | Why |
|---|---|---|---|---|
| `case_experts` | `role` select | `role` text | `case_id`, `expert_id`, `role_id`→`roles_management` | `types/allocation.ts` + `lib/pb-collections.ts` use `role_id`; hooks updated to match |
| `users.role` | select(6) | text | text | code compares strings |
| `users` fields | `country_code` | `organization_name,user_type,message,attachments` | union | profile/admin UI |
| `users.createRule` | `""` | blocks `is_active=true` self-signup | admin **or** non-admin role | registration forms send `is_active=true` |
| `cases.createRule` | `""` | authenticated only | `""` | registration/enrollment create cases before login |
| `profile.createRule` | `""` | owner only | `""` | registration creates profiles before login |
| `blog_pages.category` | text | relation | text | code writes a string |
| `info_pages.icon` | file | text | file | `updateIcon()` uploads a file |
| `expert_profiles.specialization_type` | text | json | text | code stores/reads comma-separated |
| `expert_profiles` | — | drops legacy | union (keeps `nationality`, `client_type`, `preferred_languages`, `full_legal_name`) | `ExpertApproval.tsx` still reads them |
| `programs` / `public_lectures` | json/select | text | code-compatible mix | `pb-training.ts` / `pb-lectures.ts` |
| `event_registrations` / `event_certificates` ids | relation | text | text | code casts to string |
| `settings` | `payment_bank_details` | `key/value/data` | union | `usePaymentSettings` reads `payment_bank_details` |
| `tool_types` | `name` | + user relation | `name` + optional extras | legacy fallback; `lookups(type="tool_types")` is primary |

New collections/views added from the fork: `portals`, `experts_public`,
`internal_messages`, `case_feedback`, `expert_bank_details`,
`expert_display_settings`. `public_lectures_public` was kept.

## Hook fixes

- `pb_hooks/allocation-save.pb.js` — reads/validates `role_id`, writes `role_id`.
- `pb_hooks/lib/assignment-validation.js` — validates `role_id` and checks
  duplicates on `case_id + expert_id + role_id`.

## Verification performed

- `npx tsc --noEmit` → 0 errors; `npx eslint` → 0 errors (153 pre-existing warnings).
- Snapshot re-imports into a fresh v0.31 instance (`PUT /api/collections/import` → 204, 28 collections).
- `seed.mjs` creates 10 lookups, 4 roles, 4 portals, settings, display settings and an admin; admin login returns `role=super_admin, is_active=true`.
- Hooks load with no errors; valid `role_id` create → 200, invalid → rejected; allocation endpoint → 200.
- Unauthenticated registration simulation: user + profile + case create → 200; self-creating an `admin` → 400.
- `experts_public` and `public_lectures_public` views query successfully.
